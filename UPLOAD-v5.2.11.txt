WHY THIS RELEASE
A manual RUN SPORTS TICKER AI could previously pass up to 40 stories through six-record batches, with each batch retrying three times. One click could therefore burst as many as 21 OpenAI requests and trigger HTTP 429.

V5.2.11 CHANGES
- Replaces the legacy Sports Ticker AI request storm with paced 20-record batches.
- Automatic ticker AI: at most 20 AI-reviewed candidates / 1 batch per pass.
- Manual ticker AI: at most 40 AI-reviewed candidates / 2 batches per pass.
- Remaining qualifying ticker stories are retained as deterministic rules-fill items so the feed can remain verbose without multiplying OpenAI requests.
- Serializes Sports Ticker OpenAI work against the legacy editorial refresh lock.
- Honors Retry-After when OpenAI provides it.
- Uses bounded exponential backoff with jitter for temporary 429 rate limits.
- Stops retrying immediately for quota/spend/credit errors such as credit_balance_exhausted or insufficient_quota.
- Preserves the last-good Sports Ticker on every OpenAI failure.
- Adds a backend cooldown after persistent 429s so repeated button clicks cannot hammer the API.
- The Settings utility now displays the active retry countdown while the previous ticker continues scrolling.
- Operator wait window expanded to five minutes so a legitimate Retry-After can complete without a false browser timeout.
- v5.2.10 motion/scroll performance improvements are retained unchanged.
- Frontend, backend, cache generation, and deployment preflight advance together to v5.2.11.
