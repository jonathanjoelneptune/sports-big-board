Sports Big Board v5.0.1 — UI-Thread / Feedback-Loop Hardening
===============================================================

WHY THIS RELEASE EXISTS
-----------------------
Observed failure: while a game video continued playing normally, the Sports Big Board
UI became non-responsive and clicks no longer executed. The same board lock could still
be reproduced around the known USC playback path.

The continued video progress is important evidence: the media transport was alive while
the browser's application/UI thread was being saturated.

ROOT CAUSE CLOSED IN v5.0.1
---------------------------
The v5.0.0 control plane made every Playback Session emission observable by the new
orchestrator/App Store. Native/direct video is sampled by the legacy playback-sync loop
at 250 ms. That loop could repeatedly publish the same PLAYING state even though nothing
material changed.

Under v5.0.0 the duplicate observation could fan out as:

  native poll (250 ms)
      -> setPlaybackUi(PLAYING)
      -> Playback Session emit
      -> v5 Orchestrator mirror
      -> App Store dispatch
      -> deep clone of current state/event payload
      -> subscribers / diagnostics / DOM work

This work could repeat indefinitely while the video decoder continued independently.
Large score/provider payloads made the cost worse.

v5.0.1 changes this control plane from level-triggered to edge-triggered:

  transport poll -> no material change -> NO session emit -> NO orchestrator mirror
                 -> NO App Store commit -> NO duplicate DOM work

IMPLEMENTED
-----------
1. architecture/app-store-v5.js
   - v5.0.1 / schema 1.1.
   - Branch-local immutable updates instead of deep-cloning the entire state per action.
   - Compact canonical event projection for the hot playback state.
   - Duplicate PLAYING, legacy-selection and equivalent state updates are no-ops.
   - Added dispatch/commit/no-op/snapshot/max-dispatch/max-emit health telemetry.

2. architecture/playback-orchestrator-v5.js
   - Mirrors Playback Session only when selection/state materially changes.
   - Duplicate PLAYING observations do not dispatch App Store actions.

3. architecture/playback-session.js
   - Repeated identical transitions no longer emit.
   - Repeated identical adapter assignment no longer emits.
   - Repeated unchanged audible ownership no longer emits.

4. app.js
   - setPlaybackUi() is idempotent through lastPlaybackUiMode.
   - Native 250 ms sync only publishes a UI state transition when the observed state changes.
   - Playback diagnostic DOM rendering is key-deduplicated.

5. architecture/main-thread-guard-v5.js (new)
   - Measures browser event-loop delay every 250 ms.
   - WARN threshold: 350 ms.
   - CRITICAL threshold: 1200 ms.
   - Provides cooperative browser-frame yielding to certification only.
   - Never owns or changes playback.

6. architecture/comprehensive-site-certification.js
   - Schema 3.1.
   - Stops stacking interactions if the browser is already saturated.
   - Yields between high-impact interactions.
   - Reports UI_THREAD warning/critical/max-lag evidence.
   - Reports App Store dispatch/commit/no-op/max-dispatch/max-emit evidence.
   - A critical UI-thread stall is blocking certification evidence.

7. tests/test_v501_ui_thread_hardening.js (new)
   - Uses a deliberately large USC-like event/provider payload.
   - Verifies provider/timeline bulk data never enters the hot App Store projection.
   - Feeds 100 duplicate PLAYING observations through Playback Session -> Orchestrator.
   - Verifies zero additional App Store revisions from those duplicate observations.
   - Verifies duplicate app-level PLAYBACK_PLAYING actions are no-ops.

8. Release handshake / retained v5 tests
   - VERSION / core-model / index cache generation -> 5.0.1.
   - Retained v5.0 architecture tests accept the v5.0.x foundation line.

NO GAME-SPECIFIC FIX
--------------------
There is no USC event ID, team-name, league-specific, or media-ID exception in this
hardening. USC remains a useful regression trigger, but the fix applies to every game,
transport and certification interaction.
