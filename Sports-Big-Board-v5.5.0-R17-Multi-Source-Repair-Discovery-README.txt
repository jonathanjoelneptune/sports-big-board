Sports Big Board v5.5.0 R17 — Multi-Source Repair Discovery

WHY R17
R16 successfully separated certification from repair, but production evidence showed:
- 283 repair jobs queued
- 128 repair jobs attempted
- 127 exhausted
- 0 new candidates
- 0 certified replacements
- 0 canonical promotions

The orchestration worked. Discovery did not.

R17 preserves the R16 audit/repair separation and canonical write-back contract while
replacing repeated discovery calls with a materially different source ladder.

R17 DISCOVERY LADDER

STAGE 0 — LOCAL_CATALOG
Deep-search the normalized Sports Big Board source-media catalog for forgotten,
unassigned, superseded, or previously discovered GAME media matching both participants
and the event publication-date window.

A candidate must meet strict participant/date evidence before it is attached to the
target event as:
  UNVERIFIED / MEDIA_REPAIR_DISCOVERED

STAGE 1 — REGISTERED_PROVIDERS
Run the existing Sports Big Board event discovery authority ONCE, rather than repeating
the same endpoint three times. This retains the current official/provider adapters,
including the league-specific/ESPN/Highlightly/official lanes already registered in
Sports Big Board.

The stage records:
  result count
  genuinely new assets
  known/duplicate assets
  rejected assets

STAGE 2 — OFFICIAL_YOUTUBE_INDEX
Build and periodically refresh a persistent local index of uploads from empirically
trusted YouTube channels already producing ASSIGNED or PLAYED Sports Big Board GAME
media.

Channel trust is derived from the canonical catalog:
- >= 2 PLAYED GAME assets, or
- >= 5 ASSIGNED GAME assets

Index refresh uses:
  channels.list
  playlistItems.list

Candidate validation uses:
  videos.list

It does NOT use search.list.

This is intentionally compatible with the existing YouTubeGateway operation isolation:
a search.list quota exhaustion cannot disable channels.list, playlistItems.list, or
videos.list.

The default index refresh:
- up to 40 trusted channels
- up to 2 recent upload pages per channel
- every 6 hours

Each repair event matches the local index by:
- both participant identities
- strict event publication-date window
- highlights/recap semantics
- public/embeddable videos.list status

Any match still enters as UNVERIFIED and must pass controlled Chrome playback before
promotion.

STAGE 3 — GENERIC_YOUTUBE_SEARCH
search.list is now a scarce last-resort resource rather than the main broad-search path.

Priority policy:
- NO_MEDIA / UNPLAYABLE may use it immediately.
- DEGRADED does not use generic search until a later repair attempt.
- if search.list is quota/cooldown blocked, the repair job sleeps until at least the
  gateway-provided retry/reset time instead of repeatedly re-running the same ladder.

COOLDOWN / LOOP REPAIR
R16's synchronization could reopen WAITING_RETRY work whenever the audit remained
DEGRADED/UNPLAYABLE/NO_MEDIA. R17 preserves a future cooldown when health/target have
not worsened.

Retry policy:
- event age <= 2 days: 6 hours
- event age 3–7 days: 24 hours
- event age > 7 days: 7 days
- YouTube quota blocked: never before the gateway-provided reset/cooldown

Because R17 is a materially new strategy, existing R16 WAITING_RETRY jobs receive ONE
immediate R17 retry. Once an R17 job records strategy=R17_MULTI_SOURCE_LADDER, normal
cooldown preservation applies.

DEPLOY/RESTART REPAIR
Repair jobs left SEARCHING or CERTIFYING by service restart are returned to PENDING.
This is safe because no repair link becomes canonical until its PLAYED promotion was
successfully committed.

PERSISTENT OBSERVABILITY
New tables:
  history_media_repair_source_attempt
  history_media_repair_youtube_index

Per-source telemetry records:
  stage
  provider
  query
  results
  new candidates
  known/duplicates
  rejected
  quota blocked
  retry time
  details

The Media Audit operator panel now shows:
  Discovery stage
  Stage yield
  Source telemetry
  YouTube indexed count
  YouTube search quota blocks

CANONICAL WRITE-BACK IS UNCHANGED
Discovery never self-promotes.

Every repaired asset still follows:
  DISCOVERED
  -> UNVERIFIED / MEDIA_REPAIR_DISCOVERED
  -> controlled Chrome PLAYING_TIME_ADVANCED
  -> ASSIGNED / MEDIA_REPAIR_CERTIFIED
  -> history_media_canonical_package updated
  -> audit health updated
  -> normal Sports Big Board playback uses the repaired link everywhere
