Sports Big Board v5.0.3 — Score Click Authority / Pathological Event Hardening

ROOT CAUSE CLOSED
- v5.0.2 still evaluated scoreCardPlayableItems(m) as an argument to playGameHighlights()
  directly inside the ribbon click handler.
- JavaScript evaluates function arguments before entering playGameHighlights(), so the old
  synchronous resolver could monopolize the main thread before the v5 intent, cooperative
  Media Plan builder, main-thread yields, or score-click telemetry existed.
- This exactly permits the prior video to keep playing while the board stops responding.

RUNTIME CHANGES
- Score-ribbon click now passes no precomputed media. The synchronous click boundary creates
  v5 ownership only; media planning starts asynchronously after the transaction exists.
- Removed pointerenter / pointerdown / focus score-media priming from individual score cards.
- primeScoreIntent() may prime only the exact candidate immediately; whole-ribbon warm-set
  reconciliation is deferred.
- Historical no-media score clicks also use the cooperative planner instead of re-running
  scoreCardPlayableItems() synchronously.
- Ordinary playGameHighlights() callers cannot inject a precomputed media array unless marked
  trustedProvidedItems=true.
- Nested recap/media alternate expansion is iterative, depth-limited to 2, capped at 96 total
  expanded assets, and each recapAlternates edge is capped by the existing 12-alternate limit.
- Score-session startup failures remain local and do not contribute to the destructive global
  playback-engine reset threshold.
- App Store schema 1.3 prevents CLEAR_EVENT underneath an active event-owned transaction unless
  the v5 orchestrator explicitly owns the teardown (or force=true).
- SelectedEvent applies the same active-transaction clear protection.

DIAGNOSTICS / CERTIFICATION
- Comprehensive Certification schema 3.3.
- Persistent score-click breadcrumb records stages including CLICK_RECEIVED, INTENT_CREATED,
  PLAN_START, PLAN_BUILT, SELECTION_START, SELECTION_RESOLVED, CANDIDATE_PLAN_RESOLVED,
  PROGRAM_COMMITTED, TUNE_REQUESTED and TUNE_DISPATCHED.
- Last breadcrumb is persisted in sessionStorage so it survives a page reload after a browser
  lock and can show the last completed stage.
- Playback rows report clickStage and bounded media-version expansion telemetry.
