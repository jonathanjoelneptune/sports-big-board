WHAT v4.7.15 CHANGES
1. Filter fast path / DOM lifecycle
   - Full renders build one complete all-league score-card bank for the selected date.
   - League filter changes reuse the exact existing score-card DOM nodes and only
     change visibility instead of rebuilding every card.
   - The bank is validated against stable game identities before reuse. A stale or
     incomplete bank automatically falls back to the canonical full render.
   - Existing card click/playback handlers remain attached because game-card nodes
     are reused, not cloned.

2. Generation-scoped availability
   - Score-card availability is indexed for the entire selected date rather than
     only the currently visible league.
   - Filter-only renders reuse the date snapshot.
   - Date/media/Day-State renders rebuild it so freshness semantics are preserved.
   - Canonical Day State playable media, verified session media, and positive legacy
     resolution are all counted as already-known playable media.

3. Media-readiness certification
   - The efficiency test now consults both render telemetry and the authoritative
     per-date availability ledger.
   - Zero-inventory state is NO_KNOWN_PLAYABLE_MEDIA.
   - This fixes the v4.7.14 mismatch where AVAIL_KNOWN_MEDIA_GAMES could be non-zero
     while MEDIA_KNOWN_GAMES remained zero/N/A.

4. DOM certification
   - Baseline and restored DOM counts are sampled over stabilization windows.
   - Report adds DOM baseline, peak, restored count, stable growth, peak growth,
     filter fast paths, card-bank builds, availability snapshot reuse, and filter
     apply p95.
   - Any scored FAIL now propagates to the overall efficiency result.
