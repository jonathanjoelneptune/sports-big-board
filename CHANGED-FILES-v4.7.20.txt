Sports Big Board v4.7.20 — Game Center + Historical Playback Regression Recovery
Base: v4.7.19

ROOT CAUSES CONFIRMED
1. Game Center `no-active-consumers`
   - architecture/request-broker.js immediately aborted an interactive shared GET when
     the last consumer released it.
   - A replacement Game Center load could attach to that already-aborted inflight entry
     before its promise/finally removed the entry, surfacing the literal abort reason
     `no-active-consumers` in Game Center.
   - v4.7.19's multisport linescore module also issued a fallback SBB_GAME_CENTER.get(),
     creating a second request owner and making the handoff race much easier to hit.

2. Historical WATCH -> FIND regression
   - v4.7.19 invalidated every prior Day State generation even when the historical
     snapshot was healthy.
   - Rebuilt Day State then re-ran the generic media matcher over relationships already
     persisted as canonical ASSIGNED EVENT_MEDIA, which could strip playable media at
     the read boundary.

3. LLWS still FIND
   - Recovering only relationship rows that still contained SPECIAL_EVENT_* proof was
     insufficient once generic repair had already overwritten/demoted legacy evidence.
   - v4.7.20 replays the actual v4.6.16 special-event associator against persisted LLWS
     source media after competition/source registration is ready.

BEHAVIORAL CHANGES
- Request Broker adds a 75 ms orphan-consumer grace period.
- New requests never coalesce onto an already-aborted or settled inflight entry.
- Old inflight finally handlers delete the map entry only if they still own that key,
  preventing an old aborted request from deleting its replacement request.
- ui/game-center-view.js remains the sole Game Center request owner.
- Multisport linescore/win-probability chrome is read-only and consumes SBB_GAME_CENTER.peek().
- Day State accepts exact canonical GAME media already returned from normalized ASSIGNED
  EVENT_MEDIA instead of re-proving it with the generic title/team matcher.
- Non-empty historical snapshots survive read-model generation changes for first paint
  while v4.7.20 refreshes them in the background.
- Targeted Day State refreshes are regression guarded: a repair cannot replace a day
  with fewer games or fewer playable cards than the snapshot it started with.
- LLWS startup recovery invokes special_event_media_v4616.reassociate() directly and
  refreshes only dates with actual playable LLWS associations.
- Silver compatibility and CFB trusted-source recovery from v4.7.19 are retained.
