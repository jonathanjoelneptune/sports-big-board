Sports Big Board v5.0.2 — Media Plan Continuity + Pathological Score-Click Guard

PURPOSE
- Preserve the v5.0.1 UI-thread fix while closing two remaining failure classes:
  1. A failed/prewarm-timeout media candidate could end a v5 transaction UNAVAILABLE even when other same-game candidates remained.
  2. One unusually dense game could perform pathological recap/media work in the synchronous score-click/UI path.

ARCHITECTURE CHANGES
1. Deterministic Media Plan continuity
   - Adds candidate attempt/rejection/exhaustion state to SBB_APP_STORE schema 1.2.
   - A single candidate failure can no longer legitimately terminate a non-empty Media Plan.
   - PLAYBACK_UNAVAILABLE with untried plan candidates is an explicit invariant error.
   - Same transactionId survives candidate 1 -> candidate 2 -> candidate N.

2. Cooperative score media planning
   - New architecture/score-media-plan-v5.js.
   - Date media scans run in bounded chunks and yield to the browser between chunks.
   - Exact/canonical event candidates remain first.
   - Planning telemetry records total scanned, accepted, yields, build time and max chunk time.

3. Current-session direct-video readiness
   - Historical PLAYBACK_READY/VERIFIED is now PROVEN_HISTORY ranking evidence.
   - Direct/native media becomes air-ready only after current-session HOT_READY / HOT_THIS_SESSION proof.
   - Unproven upstream media stays off-air while preparation occurs.

4. Indexed and bounded recap alternatives
   - Replaces hot-path full RECAP_CANDIDATE_REGISTRY scans with a canonical-game recap index.
   - Index rebuilds only when registry membership changes.
   - Repeated UI lookups use a short cache.
   - Recap alternatives are capped at four per tier and twelve total per event.
   - This is generalized protection for any unusually dense/ambiguous game; no USC/team/event-ID runtime exception exists.

5. Sport-aware Game Center completeness
   - Final-game payload quality is checked by sport.
   - Sparse football shells no longer automatically report complete simply because the request returned successfully.
